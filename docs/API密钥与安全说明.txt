RATGP · API Key 与安全说明
============================================================
更新日期：2026-11-19
对应改动：移除 .env 明文密钥，改为 BYOK（用户自带 Key）

一、为什么要改
------------------------------------------------------------
原来的做法是把 DEEPSEEK_API_KEY 写在 App/.env 里：
- 文件随项目目录一起流动（打包、备份、共享屏幕、发给同学），
  一个 52 字节的小文件极容易在压缩包里被一起带走；
- 任何能读目录的工具（IDE 插件、AI 助手、备份软件）都能读到；
- 一旦被提交进 git 或上传到公开仓库，几分钟内就会被爬虫扫到并盗刷。

本次已删除的两份文件：
- App/.env
- archive/feasibility/.env（同一把 key 的副本）

注意：删除文件不等于 key 失效。key 仍然有效，只是不再落盘。
如果这把 key 曾经出现在任何可能外传的地方（聊天、截图、仓库历史、网盘），
请到 https://platform.deepseek.com/api_keys 直接作废并重新创建（即"轮换"）。

二、现在怎么工作（BYOK）
------------------------------------------------------------
调用大模型时，Key 的来源按优先级：
1. 请求头 X-DeepSeek-Key —— 用户在页面右上角「钥匙」按钮里填的；
   只写进浏览器 sessionStorage：刷新还在，关掉标签页失效；
   不写数据库、不进日志、不进代码。
2. 系统环境变量 DEEPSEEK_API_KEY —— 开发者本机调试用。
3. 两者都没有 —— 后端返回 401，页面提示去设置。

前端统一入口：Web/lib/api.ts 的 apiFetch()，自动带请求头；
后端统一入口：App/services/llm_service.py 的 resolve_api_key() + get_client()。
get_client() 用 lru_cache(maxsize=8) 按 key 缓存，进程重启即释放。

三、已知限制（都是有意接受的取舍）
------------------------------------------------------------
1. sessionStorage 不是保险箱。
   同一浏览器里的扩展、开发者工具、XSS 都能读到它。本项目是本地
   单用户应用，风险可接受；但不要改用 localStorage（长期驻留），
   也不要把 key 放进 URL（会进访问日志）。

2. 没有用户体系。
   "有无 key"就是事实上的身份，需求/用例/报告数据仍是全局共享的。
   多人使用同一台机器时，会看到彼此的数据。用户体系属于二期。

3. 没有 HTTPS。
   本地 http://127.0.0.1 回环通信，key 不出机器。
   一旦部署到局域网或公网，必须先上 HTTPS，否则 key 会明文过网。

四、将来封装成桌面软件时的升级路径
------------------------------------------------------------
1. 绝对不要把 key 硬编码进程序。
   PyInstaller 等打包产物可以用 pyinstxtractor 还原出 pyc，字符串常量
   一眼可见；Electron 的 asar 也只是归档，不是加密。
   写死在代码里 = 公开发布你的额度。

2. 正确的本地存储方式：
   - Windows：DPAPI（CryptProtectData，绑定当前用户）+ Python keyring 库；
   - macOS：Keychain；Linux：libsecret。
   这些方案让 key 只能被当前登录用户解密，落盘也是密文。

3. 安装包内只放"输入 key"的界面，不放 key 本身。
   首次启动引导用户粘贴；可选"记住"时再走上面的系统凭据库。

4. 如果要做成"开箱即用、用户不用自己申请 key"的产品，
   就必须有自己的后端代理 + 账号体系 + 计费/限流，
   key 只存在服务器侧，客户端永远拿不到。
   这是产品形态的升级，不是打包能解决的。

五、演示时的注意事项
------------------------------------------------------------
- 演示机上可以提前在系统环境变量里设好 DEEPSEEK_API_KEY，
  演示时就不用现场粘贴；界面里粘贴也只需要一次（关标签页才失效）。
- 答辩前先在 DeepSeek 控制台确认余额和用量，避免演示中途 401/402。
- 演示结束后如果用了公共电脑，点「设置 → 清除」，或直接关掉浏览器。

六、如果 key 泄露了怎么办
------------------------------------------------------------
1. 立刻到 https://platform.deepseek.com/api_keys 删除旧 key；
2. 新建一把，更新使用处（界面粘贴一次，或改环境变量）；
3. 查看"用量/账单"，确认有没有异常调用；
4. 如果发生在 git 仓库：删文件不够，还要改写历史（git filter-repo / BFG），
   并假设它已经泄露，直接作废。
