## 一、这是什么

RATGP：**基于大模型的软件需求分析与测试用例辅助生成平台**。

主线闭环：

```
需求文档 → 解析 → AI 抽取候选需求 → 人工确认
        → 质量扫描 / 裁决 → 生成测试用例 → 人工审核
        → 追踪矩阵 → 两版文档比对 → 质量报告（CSV）
```

三条设计原则（不要破坏）：

1. **AI 提候选，人做决策**：抽取结果一律 `未审核`，用例一律 `已生成`，不会自动通过。
2. **编号由程序生成**：不采信模型自己编的编号。
3. **生成 ≠ 执行 ≠ 通过**：三件事分开记。

## 六、关键设计决策

### 1. 主键与编号

```sql
Requirement (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    req_id TEXT NOT NULL,
    project_id INTEGER NOT NULL,
    UNIQUE(project_id, req_id)
)
```

- 数据库用自增 `id` 认行；业务用 `req_id`（项目内唯一）
- 两个项目可以各自有 `CR-001`
- 编号生成：按项目 `max + 1`，格式 `CR-%03d`
- 手动新建也走同一套续号

### 2. 质量问题的稳定指纹

```python
fingerprint = sha1(f"{kind}|{','.join(sorted(req_ids))}|{','.join(sorted(words))}")[:12]
```

- 同一份数据重复扫描，指纹不变
- 需求内容改了、命中词变了，指纹变，旧裁决自然失效
- 裁决存 `QualityDecision(project_id, fingerprint, decision, note)`，`decision ∈ {open, confirmed, ignored}`

### 3. 文档坐标 `para_no`

- 是「非空块」的连续序号，段落与表格行共用一套
- 旧数据已存进 `Document.para_index`，不会重算
- 前端显示序号（1、2、3…）与 `para_no` 解耦：标题不占号，正文连续

### 4. 表格解析

- 按 `body` 顺序遍历 `<w:p>` / `<w:tbl>`
- 一行表格 = 一段，`style="Table"`
- 首行像表头（命中「编号/需求/描述/验收…」≥2）→ 当列名，数据行输出 `编号：X | 名称：Y`
- 合并单元格按 `id(cell._tc)` 去重；嵌套表格递归限 3 层

### 5. 离线态

- `load*` 失败返回空数据 + `source: "mock"` + `error`
- 页面第一行判断 `source === "mock"` → `<Offline message={error} />`
- 侧栏数字显示 `—`
- 不再有 mock 假数据

### 6. API 路径（注意有过变更）

| 能力 | 路径 |
|---|---|
| 需求状态/编辑 | `PATCH /api/projects/{pid}/requirements/{req_id}` |
| 用例编辑/审核 | `PATCH /api/projects/{pid}/cases/{tc_id}` |
| 质量裁决 | `PATCH /api/projects/{pid}/quality/issues/{fingerprint}` |
| 质量扫描 | `GET /api/projects/{pid}/quality/issues` |
| 抽取需求 | `POST /api/projects/{pid}/requirements/extract?doc_id=&replace=`（`replace` 默认 `false` 追加续号；`true` 覆盖，单事务） |
| 生成用例 | `POST /api/projects/{pid}/cases/generate` |

旧路径 `PATCH /api/requirements/{req_id}` 和 `PATCH /api/cases/{tc_id}` 已废弃。

## 七、踩过的坑与技巧

### 1. `next build` 和 `next dev` 不能同时用 `.next`

两者共用 `Web/.next`，跑 build 会把 dev 的模块映射冲掉，页面报
`__webpack_modules__[moduleId] is not a function`。

**规则**：跑 `next build` 前先确认 `npm run dev` 已停；或 build 完重启 dev。

### 2. Windows 控制台 GBK 乱码

```powershell
$env:PYTHONIOENCODING = "utf-8"
```

否则 Python 输出的中文会变成乱码（数据本身没问题）。

### 3. PowerShell 5.1 不支持 `Invoke-WebRequest -SkipHttpErrorCheck`

要么用 `curl.exe`，要么 `Invoke-RestMethod` + `try/catch` 读 `$_.Exception.Response.StatusCode`。
curl 传 JSON 的引号在 PowerShell 里会被吃掉，用 `--data-raw '{"replace":false}'` 或临时文件。

### 4. 沙箱里 `git ls-remote` 的 ssh 报 signal pipe

`git push` 本身正常；验证用 GitHub API：

```
https://api.github.com/repos/PengYangZhi487/Software_Engineering_Project/commits?per_page=1
```

### 5. `doc.paragraphs` 不含表格

必须按 body 遍历；表格文字不会出现在 `doc.paragraphs` 里。已修，见 `doc_service._iter_blocks`。

### 6. `replace=true` 是破坏性的

抽取时先删该项目全部需求+用例，再整体写入；清空与插入在同一个事务里，任何一步失败都会 `rollback`，不会留下半截数据。
默认 `false` 是追加续号；只有明确要覆盖时才传 `true`，演示时不要让不熟悉的人乱点。

### 7. seed 会清空所有项目

`tools/seed_demo.py` 的 `_reset` 删除 `Project` 全部记录，只适合单项目演示库。
默认自动备份到 `App/data/ratgp.db.bak-<时间戳>`。

### 8. 数据库迁移是幂等的，启动时自动执行

`init_db()` 会依次：

1. 建表（`IF NOT EXISTS`）
2. `_migrate_requirement_add_req_type`（补 `req_type`）
3. `migrate_requirement_pk`（旧 `req_id` 主键 → 自增 `id`）
4. `ensure_requirement_priority`（补 `priority`）
5. 建 `QualityDecision` 表

迁移前建议手动备份：

```powershell
Copy-Item App\data\ratgp.db App\data\ratgp.db.bak-手动
```

### 9. 质量指纹不是“需求内容哈希”

指纹只由 `kind + req_ids + words` 决定。只改描述、模糊词没变时，指纹不变，旧裁决继续有效——这是刻意的。

### 10. 前端 mock 数据已删

`Web/lib/data.ts` 和 `stats.ts` 已删除（离线态改用 `<Offline>`）。
如果以后要做“没后端也能看界面”的演示模式，从 git 历史里恢复 `data.ts`，或另写 `NEXT_PUBLIC_DEMO` 分支。

### 11. 测试全部用假 LLM

`unittest.mock.patch` 打桩 `llm_service.extract_requirements` / `case_service.generate_cases`，不耗额度。
测试库通过 `RATGP_TEST_TMP` 指向临时目录，不会污染真实库。
