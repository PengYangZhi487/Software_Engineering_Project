# RATGP 完整功能演示手册

> 目标：用一个「校园选课系统」项目，从空库开始，把软件的主要功能走一遍。
> 演示时长参考：**15–20 分钟**（含两次大模型调用）。

## 一、先准备什么

### 1. 演示文档（本次已生成）

| 文件 | 用途 |
|---|---|
| `demo/图书馆借阅系统需求_V1.0.docx` | 演示上传/解析/抽取；普通需求文档风格（章节 + 自然段落），含两张表格，故意包含模糊、冲突、缺验收 |
| `demo/图书馆借阅系统需求_V1.1.docx` | 演示版本比对：借阅期限 30→45 天、罚款 0.2→0.5 元、新增「座位预约」、删除「公告与推荐」 |
| `demo/需求导入示例.xlsx` | 演示「Excel 导入需求」（新书采购审批、馆际互借） |

### 2. 准备一个干净的演示环境

**推荐：用独立数据目录演示，不动你现有的数据。**

```powershell
# 桌面版（exe 支持 --data-dir）
.\build-artifacts\release\RATGP.exe --data-dir "$env:USERPROFILE\RATGP-demo"

# 或者从源码
.\venv\Scripts\python.exe desktop.py --data-dir "$env:USERPROFILE\RATGP-demo"
```

首次启动会要求设置本地锁密码（演示用简单密码即可，例如 `1234`），之后记牢。

> 如果不想用独立目录，也可以删掉 `%APPDATA%\RATGP\ratgp.db`（**先备份**），或跑 `tools/seed_demo.py --yes` 重建演示基准数据（会清空所有项目）。

### 3. DeepSeek API Key

步骤 3（抽取需求）和步骤 6（生成用例）会调用大模型，需要自己的 Key：
点右上角「钥匙」按钮粘贴，或用环境变量 `DEEPSEEK_API_KEY`。
**没有 Key 也能演示**：跳过 3、6，直接用 seed 数据演示其余功能（见文末「降级演示」）。

## 二、演示步骤

### 步骤 1：新建项目（30 秒）

1. 打开软件，侧栏顶部项目选择器 → **新建项目**；
2. 名称填「校园选课系统」，描述可留空。

**预期**：新项目被选中，侧栏数字都是 0/—，页面提示还没有文档。

> 讲：软件是单机管理台，数据存在本机；每个项目的数据按项目隔离。

### 步骤 2：上传需求文档（60 秒）

1. 进入 `/document` 文档工作台；
2. 点「上传文档」，选 `demo/图书馆借阅系统需求_V1.0.docx`，版本填 `V1.0`；
3. 上传后看左侧大纲、中间正文、右侧候选需求区。

**预期**：
- 解析出约 47 个段落、19 个标题（章节 + 小节）；
- 两张表格被展开成段落（`角色 | 主要职责 | 权限范围`、`状态 | 说明 | 是否可借` 一行一段）；
- 点正文段落，右侧显示该段关联的候选需求（此时还没有）。

> 讲：表格里的需求不会丢，一行转一段，段落编号和来源定位都保留。

### 步骤 3：AI 抽取需求（60–90 秒）

1. 点「抽取需求」；
2. 选择「覆盖并抽取」（空项目也可以直接抽取）；
3. 等待 10–30 秒（按钮显示计时）。

**预期**：`created` 约 15–25 条需求（普通文档抽取，条数以模型实际输出为准），编号 `CR-001…`，状态全部「未审核」，侧栏「需求」数字变化。

> 讲：编号是程序生成的，不采信模型自己编的；AI 只提候选，不会自动确认。

### 步骤 4：人工确认（60 秒）

1. 进入 `/requirements` 需求库；
2. 筛选「未确认」，勾选 3–5 条，点「批量确认」；
3. 打开某条需求的抽屉，点「驳回」再点「恢复」，演示状态流转。

**预期**：状态变为「已确认 / 已驳回」，侧栏确认数、模糊数同步变化。

> 讲：确认/驳回都留痕，驳回不物理删除；模糊需求会标「模糊」。

### 步骤 5：质量扫描与裁决（60 秒）

1. 进入 `/quality`；
2. 看三类问题：模糊表达（如「快速」「友好」「及时」）、需求冲突（容量 50 与 60、退课 2 周与 4 周）、缺验收条件（CR-023、CR-024）；
3. 任选一条，点「确认」或「忽略」；
4. 切换到「已裁决」筛选看结果。

**预期**：问题数、待处理数变化；同一份数据重复扫描结果一致。

> 讲：规则可复现，不靠模型每次「再看看」；裁决按内容指纹保存，需求内容变了会自动失效。

### 步骤 6：生成测试用例（60–90 秒）

1. 进入 `/cases`，点「生成用例」；
2. 勾选几条已确认需求（或全选），生成正常 / 异常 / 边界候选；
3. 等待 10–30 秒。

**预期**：生成若干条用例，状态「已生成」，按类型统计正常/异常/边界。

> 讲：用例只给已确认需求生成；AI 提候选，审核由人做。

### 步骤 7：批量审核用例（30 秒）

1. 用例页勾选 2–3 条用例；
2. 点「批量通过」；
3. 切到「已审核」筛选。

**预期**：状态变为「已审核」；追踪页覆盖率上升（已审核用例才计入覆盖）。

### 步骤 8：记录执行结果（60 秒）

1. 任选一条用例，点「记录执行」；
2. 执行结果选「失败」，实际结果写「第 51 人仍可提交」，comments 写「容量校验未生效」，执行人选「张三」，签名「ZS」；
3. 保存。

**预期**：卡片出现「最近执行：失败 · 日期」；顶部「执行记录」计数 +1。

> 讲：生成 ≠ 执行 ≠ 通过，执行是真实结果，会进报告 Excel 的执行表。

### 步骤 9：追踪矩阵与覆盖率（60 秒）

1. 进入 `/trace`；
2. 默认「汇总视图」看每条需求的用例状态；切「详细矩阵」看需求 × 用例；
3. 矩阵容器内横向滚动（表头吸顶、需求列固定），右侧看「未覆盖需求」。

**预期**：覆盖率数字可解释（至少一条已审核用例的已确认需求 / 已确认需求总数）。

> 讲：覆盖口径写死并可 SQL 复算，不是拍脑袋的百分比。

### 步骤 10：上传 V1.1 与版本比对（60 秒）

1. 回到 `/document`，上传 `demo/图书馆借阅系统需求_V1.1.docx`，版本 `V1.1`；
2. 页面出现「文档已改版 V1.0 → V1.1」提醒卡片；
3. 点「查看变更影响」进入 `/changes`。

**预期**：比对出改动：
- 借阅期限 30 天 → 45 天（changed，−30 +45）
- 逾期罚款每天 0.2 元 → 0.5 元（changed）
- 新增「座位预约」一节（added）
- 删除「公告与推荐」一节（removed）
并列出受影响的需求与用例。

> 讲：改版后能知道「哪些需求/用例要复核或重跑」，这是 Excel 难做的。

### 步骤 11：质量报告与导出（60 秒）

1. 进入 `/report`；
2. 点「导出 Excel」，页面显示保存路径（桌面版默认在 `%APPDATA%\RATGP\exports\`）；
3. 从该路径打开 xlsx，四个 Sheet：概览 / 需求清单 / 测试用例执行表 / 覆盖矩阵。

**预期**：执行表里有步骤 8 填的实际结果、comments、执行人、签名、执行时间；数字与页面一致。

> 讲：页面和文件同一份数据，交付物可复算。

### 步骤 12：导入 / 导出闭环（60 秒，可选）

1. 需求库点「导出」，页面显示保存路径（`%APPDATA%\RATGP\exports\` 下的 xlsx）；
2. 从该路径打开、在 Excel 里改一条标题、加一行；
3. 回到需求库点「导入」，上传改过的文件；
4. 提示「更新 1 条 / 新增 1 条」。

**预期**：改动回到软件，编号继续由程序维护。

> 另一个入口：需求库「导入」→「上传 Excel」选 `demo/需求导入示例.xlsx`，会新增 2 条需求（新书采购审批、馆际互借）。
> 也支持「粘贴大模型输出」：直接把 DeepSeek 返回的 JSON 贴进去。

### 步骤 13：多项目（30 秒，可选）

1. 项目选择器 → 新建「图书馆借阅系统」；
2. 切回「校园选课系统」，数据互不影响；
3. 删除空项目演示 409 → 强制删除的二次确认。

### 步骤 14：本地锁（30 秒）

1. 顶栏盾牌按钮点「锁定」→ 回到锁屏；
2. 输入密码解锁。

> 讲：这是单机门禁，防别人随手打开改数据；不是网络账号体系。

## 三、降级演示（没有 Key / 不想等大模型）

如果现场没有 Key，可以跳过步骤 3 和 6，用现成数据演示其余功能：

```powershell
.\venv\Scripts\python.exe tools\seed_demo.py --yes
```

重建后：1 个项目 · 2 个版本 · 25 条需求（14 已确认）· 12 条用例 · 10 个质量问题 · 覆盖率 43%。

然后从步骤 4（确认）开始演示，质量 / 审核 / 执行 / 追踪 / 比对 / 报告都能展示，只是没有「AI 抽取」和「AI 生成用例」两个环节。

> 注意：seed 数据集是另一套「校园选课系统」文档，和本手册的图书馆文档内容不同，不影响功能演示。

## 四、演示话术（一句话版）

> 「这是一个需求与测试用例的管理台。AI 只负责把文档变成候选需求和候选用例，确认、审核、执行、交付都由人来定；它把需求、用例、变更、执行记录串成一条可追溯、可复算的线。」

## 五、常见问题

| 问题 | 处理 |
|---|---|
| 上传后没有候选需求 | 正常，候选需求要等「抽取需求」后才有 |
| 抽取提示 401 | 右上角钥匙填 Key，或设环境变量 |
| 生成用例 0 条 | 先确认几条需求（用例只给已确认需求生成） |
| 变更页没有数据 | 需要同一项目下两个不同版本的文档 |
| 桌面版打开是空库 | 用了 `--data-dir` 或首次运行；换回默认数据目录或复制 `App\data\ratgp.db` |
| 忘了本地锁密码 | 本地无找回，删 `ratgp.db` 或恢复备份（会丢数据） |
