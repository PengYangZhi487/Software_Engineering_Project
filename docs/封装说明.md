# RATGP 桌面封装说明（B 路线：前端客户端化 + 单 Python 进程 + pywebview 壳）

> 最后更新：2026-11-24
> 适用：Windows 10/11（x64）；macOS/Linux 仅用于开发调试
> 相关文件：`desktop.py`、`App/api/web_static.py`、`tools/build_web.ps1`、`tools/build_exe.ps1`、`tools/backup.ps1`

---

## 一、架构

```
┌──────────────────────────────────────────────────────────────┐
│ desktop.py（唯一进程）                                        │
│                                                              │
│  主线程  ── pywebview 原生窗口 ──> http://127.0.0.1:<随机端口> │
│                                                              │
│  后台线程 ── uvicorn ── FastAPI app（App/api/main.py）        │
│              ├── /api/**   → 现有的 API 路由                  │
│              ├── /         → build-artifacts/web_dist/index.html     │
│              ├── /_next/** → build-artifacts/web_dist/_next/**       │
│              └── 其他深层路由 → 回落 index.html（前端路由接管） │
└──────────────────────────────────────────────────────────────┘

数据目录（首次运行自动创建）
  %APPDATA%\RATGP\
    ├── ratgp.db      SQLite 数据库
    ├── uploads/      上传的 Word/TXT
    ├── backups/      tools/backup.ps1 的备份
    └── logs/         desktop.log（运行日志）
```

三条硬约束：

1. **不改 `App/api/main.py`**：静态托管是独立模块 `App/api/web_static.py`，由桌面入口在 `app` 创建后调用 `mount_web(app)`。纯 API 模式（`uvicorn App.api.main:app`）完全不受影响。
2. **目录不存在就跳过**：找不到前端静态产物时只记一条日志，服务照常以纯 API 运行，不会崩。
3. **深层路由回落**：桌面窗口里刷新 `/requirements/` 这类路径必须回到 `index.html`，否则白屏。

| 文件 | 作用 |
|---|---|
| `desktop.py` | 桌面入口：数据目录 → 环境变量 → 后台 uvicorn → 健康检查 → pywebview 窗口 |
| `App/api/web_static.py` | `mount_web(app)`：定位并挂载静态目录，`/` 返回首页，未知路径回落 |
| `tools/build_web.ps1` | `npm run build` → 复制 `Web/out` 到 `build-artifacts/web_dist` |
| `tools/build_exe.ps1` | PyInstaller 打包成 `build-artifacts/dist/RATGP.exe`（含 hidden imports 说明） |
| `tools/backup.ps1` | 把 `ratgp.db` 复制成带时间戳的备份 |

## 二、前端静态导出（封装前提）

`Web/next.config.ts` 必须开启静态导出：

```ts
const nextConfig: NextConfig = {
  reactStrictMode: true,
  output: "export",        // 关键：next build 产出 out/
  trailingSlash: true,     // 目录式 URL：/overview/ -> out/overview/index.html
  images: { unoptimized: true },
};
```

前端访问后端的地址规则（见 `Web/lib/api.ts`）：

* **桌面/生产**：相对路径 `/api/...`（同源，不依赖端口）；`tools/build_web.ps1` 默认就是这样构建。
* **开发**：`npm run dev` 时默认打 `http://127.0.0.1:8000`。
* **临时指定**：`NEXT_PUBLIC_API_BASE=http://...`（`build_web.ps1 -ApiBase` 也支持）。

> 桌面端后端端口是**随机**的，所以生产构建里不能出现 `127.0.0.1:8000` 这种硬编码。
> `build_web.ps1` 构建完会扫一遍 bundle，发现固定后端地址会给出警告。

## 三、构建

### 3.1 环境准备

| 依赖 | 版本 | 说明 |
|---|---|---|
| Python | 3.11+ | 项目自带 `venv` |
| Node.js | 20+ | 含 npm；`Web/node_modules` 已就绪时不用重装 |
| WebView2 Runtime | 新版 Edge | Win10/11 一般已带；缺了窗口会打不开 |
| pywebview | ≥ 4.4 | `App/requirements.txt` 已列 |
| pyinstaller | ≥ 6.6 | 只有打 exe 才需要 |

```powershell
# 后端依赖（含 pywebview；pyinstaller 打包时才需要）
.\venv\Scripts\python.exe -m pip install -r App\requirements.txt
```

> 脚本执行策略：如果运行 `.ps1` 提示「未对文件进行数字签名 / 在此系统上禁止运行脚本」，
> 用一次性绕过（不必改系统策略）：
>
> ```powershell
> powershell -NoProfile -ExecutionPolicy Bypass -File .\tools\build_web.ps1
> ```

### 3.2 构建前端静态产物

```powershell
.\tools\build_web.ps1                 # npm run build → 复制到 .\build-artifacts\web_dist
.\tools\build_web.ps1 -SkipInstall    # node_modules 已存在，跳过安装
.\tools\build_web.ps1 -Sandbox        # 受限环境构建（见下）
.\tools\build_web.ps1 -UseExistingOut # 只复制已存在的 Web\out，不重新构建
.\tools\build_web.ps1 -ApiBase http://127.0.0.1:8000   # 仅前后端分离调试时用
```

**受限环境（DSH 沙箱 / 部分 CI）**：这类环境禁止 `child_process.fork` 和管道，
`next build` 的默认构建 worker 会报 `spawn EPERM`；强行开 workerThreads 又可能报
`DataCloneError`。前端仓库里已提供 `Web\scripts\build-sandbox.ps1`（设
`RATGP_BUILD_SANDBOX=1` + 注入 `NODE_OPTIONS` 补丁，让 worker 走线程而不是 fork）。
`build_web.ps1` 的处理顺序：

1. 检测到 `DSH_*` 环境变量且存在该脚本 → 直接走 `build-sandbox.ps1`；
2. 否则正常 `npm run build`；
3. `npm run build` 失败且输出里出现 `EPERM` / `DataCloneError` → 自动改用
   `build-sandbox.ps1` 重试；
4. 想强制走受限路径：`-Sandbox`。

普通开发机不需要关心这些，`npm run build` 即可。

脚本会：

1. 校验 `Web/next.config.*` 是否有 `output: 'export'`（没有就直接报错，避免白白构建）；
2. `node_modules` 缺失时自动 `npm ci` / `npm install`；
3. 在 `Web/` 里执行 `npm run build`；
4. 清空并复制 `Web/out` → `build-artifacts/web_dist/`，检查 `index.html`；
5. 扫描 `build-artifacts/web_dist/_next/**/*.js` 是否残留固定后端地址，有则警告。

### 3.3 先跑起来看看

```powershell
.\venv\Scripts\python.exe desktop.py
```

窗口打开后地址栏（不可见）实际是 `http://127.0.0.1:<随机端口>/`。
不想开窗口、只想确认后端和静态托管正常：

```powershell
.\venv\Scripts\python.exe desktop.py --no-window --port 8123 --exit-after 20
# 另开终端
curl.exe http://127.0.0.1:8123/api/health
curl.exe -I http://127.0.0.1:8123/
```

### 3.4 打包 exe

```powershell
.\venv\Scripts\python.exe -m pip install pyinstaller
.\tools\build_exe.ps1                 # 单文件 exe：build-artifacts\dist\RATGP.exe
.\tools\build_exe.ps1 -OneDir         # 目录版：build-artifacts\dist\RATGP\（启动更快）
.\tools\build_exe.ps1 -Console        # 保留控制台，排查打包后的问题
.\tools\build_exe.ps1 -DryRun         # 只打印 PyInstaller 命令，不执行
```

PyInstaller 关键参数（脚本里已固定，`-DryRun` 可看到完整命令）：

| 参数 | 原因 |
|---|---|
| `--collect-submodules App` | API 层按模块路径导入 routers/services，冻结后要确保都在 |
| `--collect-submodules uvicorn` | uvicorn 运行时才选 loop / HTTP / WS 实现（`uvicorn.loops.auto`、`uvicorn.protocols.http.h11_impl`、`uvicorn.lifespan.on`…），静态分析看不到 |
| `--collect-all webview` | pywebview 运行时选后端（Windows：EdgeChromium + winforms），要带上 `webview.platforms.*` |
| `--hidden-import clr` | pywebview 在 Windows 经 pythonnet（clr）调 WinForms，native 扩展只能显式声明 |
| `--add-data "<build-artifacts\web_dist>;web_dist"` | 静态产物打进包里（脚本自动传绝对路径）；`web_static.py` 也会在 `sys._MEIPASS\web_dist` 找 |
| `--windowed` | 生产不弹控制台；`-Console` 可切换 |

产物：`build-artifacts\dist\RATGP.exe`（onefile）或 `build-artifacts\dist\RATGP\`（onedir）。

> 打 exe 前必须先构建 `build-artifacts\web_dist`，脚本会检查其中的 `index.html`。
> 打包后的冒烟：`build-artifacts\dist\RATGP.exe --no-window --port 8123 --exit-after 5`。
>
> **受限环境注意**：onefile 启动时要把自身解压到 `%TEMP%\_MEIxxxx`。在 DSH 沙箱 / 某些禁用临时目录写入的策略下会报
> `PYI-xxxx: Failed to create parent directory structure`，此时改用 `-OneDir`（`build-artifacts\dist\RATGP\RATGP.exe`，不需要解压），
> 或在真实桌面（资源管理器双击）运行 onefile。onedir 已验证可正常启动（health / 首页 / 静态路由都通过）。
>
> 体积参考（2026-11 实测，精简依赖后）：onefile **28.1 MB**；onedir 目录 **50.5 MB**。
> 精简方式：`App/requirements.txt` 不再安装 streamlit / pandas / python-dotenv（App 不用，只有 archive 旧版用），
> 用一个独立的精简环境打包：
>
> ```powershell
> python -m venv venv-lite
> .\venv-lite\Scripts\python.exe -m pip install -r App\requirements.txt
> .\tools\build_exe.ps1 -Python .\venv-lite\Scripts\python.exe            # onefile
> .\tools\build_exe.ps1 -Python .\venv-lite\Scripts\python.exe -OneDir    # onedir
> ```
>
> 原 `venv`（含 pandas/streamlit）保留给 archive 旧版和日常开发用；打包只认 `venv-lite`，所以产物不会带历史依赖。

## 四、运行方式

| 场景 | 命令 | 说明 |
|---|---|---|
| 桌面版（推荐） | `.\venv\Scripts\python.exe desktop.py` | 单进程，窗口 + API + 静态托管 |
| 桌面版（无窗口） | `... desktop.py --no-window --port 8123` | 排查/CI/远程调试 |
| 纯后端开发 | `... -m uvicorn App.api.main:app --reload --port 8000` | 不挂前端，仍是 API 门面 |
| 前后端分离开发 | 后端 8000 + `cd Web; npm run dev` | 前端默认打 8000 |
| 打包后 | `build-artifacts\dist\RATGP.exe` | 数据目录同桌面版 |

`desktop.py` 参数：

| 参数 | 默认 | 说明 |
|---|---|---|
| `--no-window` | 关 | 只起 HTTP 服务，不开 pywebview 窗口 |
| `--port` | 自动挑空闲端口 | 固定端口（排查 / 演示用） |
| `--host` | `127.0.0.1` | 桌面场景不要改成 `0.0.0.0` |
| `--data-dir` | `%APPDATA%\RATGP` | 等价于 `RATGP_DATA_DIR` |
| `--db` | `<数据目录>\ratgp.db` | 等价于 `RATGP_DB` |
| `--debug` | 关 | webview 调试工具 + DEBUG 日志 |
| `--health-timeout` | 30 | 等待 `/api/health` 的秒数 |
| `--exit-after` | 0（一直运行） | 仅 `--no-window`：服务就绪 N 秒后自动退出，便于冒烟测试 |

退出码：`0` 正常；`2` 数据目录/参数错误；`3` 后端未就绪；`4` 缺少 pywebview。

## 五、数据目录

| 平台 | 默认位置 |
|---|---|
| Windows | `%APPDATA%\RATGP`（如 `C:\Users\<你>\AppData\Roaming\RATGP`） |
| macOS | `~/Library/Application Support/RATGP` |
| Linux | `$XDG_DATA_HOME/RATGP` 或 `~/.local/share/RATGP` |

首次运行时自动创建 `ratgp.db`、`uploads/`、`backups/`、`logs/`，并放一份 `README.txt` 说明各目录用途。

环境变量（优先级从高到低：命令行参数 > 环境变量 > 默认值）：

| 变量 | 作用 |
|---|---|
| `RATGP_DATA_DIR` | 数据目录（数据库、上传、备份、日志都在下面） |
| `RATGP_DB` | 数据库文件路径 |
| `RATGP_UPLOAD_DIR` | 上传目录（默认 `<数据目录>/uploads`） |
| `RATGP_WEB_DIR` | 前端静态目录（默认自动找 `build-artifacts/web_dist/`、根 `web_dist/` 或 `Web/out/`） |

迁移/换机：把整个 `%APPDATA%\RATGP` 复制到新机器同一位置即可。
卸载/重置：关掉 RATGP，删除该目录。

> 注意：`App/api/config.py` 和 `App/dao/db.py` 在**导入时**读环境变量，
> `desktop.py` 因此严格按「先准备目录和环境变量，再 import App」的顺序执行。
> 自己写启动脚本时别反过来。

### 静态目录查找顺序（`web_static.py`）

1. `RATGP_WEB_DIR`
2. PyInstaller 解包目录 `sys._MEIPASS/web_dist`
3. `build-artifacts/web_dist/`（推荐位置，`build_web.ps1` 默认输出）
4. 仓库根目录 `web_dist/`（旧位置，兼容）
5. 仓库根目录 `Web/out/`（直接 `next build` 的产物）

第一个包含 `index.html` 的目录生效；都没有时打印「跳过静态托管」，服务仍是纯 API。

### 路由回落规则

| 请求 | 行为 |
|---|---|
| `/` | 返回实际挂载目录的 `index.html`（通常是 `build-artifacts/web_dist/index.html`；替换 `main.py` 里的 API 介绍 JSON，仅挂载后生效） |
| `/assets/x.js`、`/_next/...` | 命中文件则返回文件；未命中返回 404 |
| `/requirements`、`/cases/` 等 | 未命中且无扩展名 → 返回 `index.html`（前端路由接管） |
| `/api/...` | 走 FastAPI；`/api/不存在` 仍是 404 JSON，不会被前端首页吞掉 |
| `/docs`、`/openapi.json` | 保持 FastAPI 自带文档 |

## 六、备份与恢复

```powershell
.\tools\backup.ps1                                  # 备份默认数据目录
.\tools\backup.ps1 -Keep 20                         # 只保留最近 20 份
.\tools\backup.ps1 -DataDir D:\RATGP-data           # 指定数据目录
.\tools\backup.ps1 -DbPath .\App\data\ratgp.db      # 直接指定 db（开发环境）
```

生成文件：`<数据目录>\backups\ratgp-yyyyMMdd-HHmmss-fff.db`。

* 脚本会检查 `ratgp.db` 是否存在，不存在时退出码 `2`（并提示先运行一次 RATGP）。
* 如果数据库处于 WAL 模式且 `ratgp.db-wal` 里有未落盘事务，会把该文件一并复制为
  `<备份名>-wal`；恢复时两个文件要放回同一目录。
* **最稳妥**的做法仍然是：关掉 RATGP 再备份。

恢复：

```powershell
# 1. 关掉 RATGP
# 2. 先备份当前库（防止恢复错了）
Copy-Item "$env:APPDATA\RATGP\ratgp.db" "$env:APPDATA\RATGP\ratgp.db.before-restore"
# 3. 用备份覆盖
Copy-Item "$env:APPDATA\RATGP\backups\ratgp-20261124-211500-123.db" "$env:APPDATA\RATGP\ratgp.db" -Force
# 4. 如果备份带 -wal，也一起放回
# 5. 重新启动 RATGP
```

## 七、排障

| 现象 | 排查 |
|---|---|
| 窗口空白 / 404 | 先看 `%APPDATA%\RATGP\logs\desktop.log`；确认 `build-artifacts\web_dist\index.html` 存在（`tools/build_web.ps1` 跑过） |
| 窗口打不开、提示缺 WebView2 | 安装 [WebView2 Runtime](https://developer.microsoft.com/microsoft-edge/webview2/)；或用 `--no-window` 先用浏览器验证 |
| `未找到前端静态产物` 日志 | 静态目录没构建或位置不对；`--no-window` 下访问 `/` 会看到 API 门面 JSON 而不是页面 |
| `未安装 pywebview` | `.\venv\Scripts\python.exe -m pip install pywebview` |
| 端口被占用 | 默认随机端口一般不会冲突；固定端口时换一个，或去掉 `--port` |
| 页面里接口 404 / CORS | 生产构建必须是同源相对路径；重新跑 `tools/build_web.ps1`，看是否有「固定后端地址」警告 |
| 打包后启动即崩 | 用 `-Console` 重新打包看报错；确认 `--collect-submodules uvicorn`、`--collect-all webview`、`--hidden-import clr` 都在（用 `-DryRun` 核对） |
| `npm run build` 报 `DataCloneError: ()=>null could not be cloned` | 先单独在 `Web\` 里跑 `npm run build` 复现，属于前端构建问题（Next 静态生成 worker 序列化），不是封装脚本的问题；修好前端再重跑 `build_web.ps1` |
| `next build` 报 `spawn EPERM` | 受限环境（DSH 沙箱 / 某些 CI）禁止 fork；用 `.\tools\build_web.ps1 -Sandbox`（内部走 `Web\scripts\build-sandbox.ps1`）；`build_web.ps1` 在检测到 `DSH_*` 环境变量或失败信息含 EPERM 时会自动切换 |
| 数据「丢了」 | 检查是否用了不同的 `RATGP_DATA_DIR`；看 `%APPDATA%\RATGP\ratgp.db` 的修改时间 |

日志：`%APPDATA%\RATGP\logs\desktop.log`（含 uvicorn 与 `ratgp.api` 的日志）。

## 八、自检清单（改完封装相关代码后跑）

```powershell
$py = ".\venv\Scripts\python.exe"

# 1. 前端静态构建
.\tools\build_web.ps1 -SkipInstall

# 2. 单进程冒烟：健康检查 + 首页 + 深层路由回落
& $py desktop.py --no-window --port 8123 --exit-after 15
curl.exe -s http://127.0.0.1:8123/api/health
curl.exe -s -o NUL -w "%{http_code}`n" http://127.0.0.1:8123/
curl.exe -s -o NUL -w "%{http_code}`n" http://127.0.0.1:8123/requirements/

# 3. 备份脚本
.\tools\backup.ps1 -DataDir "$env:APPDATA\RATGP"

# 4. 后端测试不受影响
& $py -m pytest tests -q
```

预期：`/api/health` 返回 `{"status":"ok","db":"ok",...}`；`/`、`/requirements/` 返回 `200`（HTML）；备份目录出现
`ratgp-*.db`。

## 九、和旧做法（A 路线）的区别

| | A 路线（已放弃） | B 路线（当前） |
|---|---|---|
| 进程 | PyInstaller 起后端 + 另起浏览器 | **单进程**：uvicorn 后台线程 + pywebview 窗口 |
| 前端 | Node 服务或 `next start` | `next build` 静态导出，Python 同源托管 |
| 数据 | `App/data/`（跟着程序目录） | `%APPDATA%\RATGP`（用户数据目录） |
| 分发 | 需要装 Node / 手动开浏览器 | 一个 `RATGP.exe` |
